# 날자 아카이브 편집·검색 전략

이 문서는 날자 아카이브의 새 글을 작성할 때 적용하는 편집 기준이다. 목표는 단순히 검색량이 큰 키워드를 잡는 것이 아니라, 사람들이 사용하는 말과 날자가 새로 만들어 가는 언어를 연결하는 것이다. 게시 주제는 사용자가 확정하며, 이 문서의 검색 기준으로 AI가 주제를 대신 고르거나 바꾸지 않는다.

## 기본 관점

지적장애, 학습권, 문해력, 유추, AI는 아직 대중 검색량이 큰 주제가 아니다. 그래서 날자 아카이브는 검색량만 좇지 않는다. 이미 검색하는 사람을 만나고, 아직 검색어가 없는 고민에 이름을 붙이고, 공유 가능한 글을 만들며, 긴 시간의 신뢰를 쌓는 방식으로 운영한다.

## 네 가지 방향

### 1. 이미 검색하는 사람을 잡기

현장에서 실제로 검색할 가능성이 높은 말로 글의 입구를 만든다.

- 지적장애 학습자료
- 발달장애 읽기 쉬운 책
- 느린학습자 문해력
- 특수교육 AI
- 쉬운 정보 만들기
- 발달장애 성인 프로그램

이 표현들은 검색 입구의 후보이며, 실제 검색량을 확인한 목록은 아니다. 용어는 글이 실제 다루는 모집단에 맞춘다. 지적장애인만 다루면 지적장애인을 중심 용어로 쓰고, 공식 조사나 내용이 지적장애인과 자폐성장애인 등을 포괄하면 발달장애인을 정확한 범주명으로 쓴다. 발달장애를 더 넓은 다리 검색어로만 사용할 때는 글이 실제로 다루는 범위를 도입부에서 명확히 밝힌다. 참고자료의 공식 명칭은 원문 그대로 둔다.

### 2. 아직 검색어가 없는 고민에 이름 붙이기

사람들이 아직 검색하지 않더라도 읽는 순간 자기 고민임을 알아볼 수 있는 문장을 만든다.

- 쉬운 글만으로 충분하지 않다.
- 배운 것이 삶으로 이어지지 않는다.
- 유추력이 필요하다.
- 정보 접근은 시작이고, 이해와 선택이 권리의 실제 작동이다.

이 문장들은 날자 아카이브의 고유한 설명 언어가 된다.

### 3. 검색보다 공유 가능한 글 만들기

이 분야는 검색량보다 교사, 부모, 복지관, 치료사, 활동가, 연구자 사이의 공유가 중요할 수 있다. 글은 단체 대화방, 강의자료, 제안서, 뉴스레터에서 공유되어도 독립적으로 의미가 통해야 한다.

공유 가능한 글의 기준:

- 제목만 봐도 현장의 고민이 드러난다.
- 첫 문단이 문제를 바로 설명한다.
- 핵심 요약이 있다.
- 출처와 날자꾸러미 관점을 구분한다.
- 제품 홍보보다 문제 정의와 관점 정리에 먼저 힘을 둔다.

### 4. 긴 시간의 신뢰 만들기

AI 검색과 검색엔진은 웹에 쌓인 일관된 문장, 내부 링크, 출처, 작성 주체를 읽는다. 지금 검색량이 작아도 같은 주제를 꾸준히 정확한 언어로 쌓으면 나중에 이 주제를 설명하는 곳으로 인식될 가능성이 생긴다.

## 키워드 체계

### 큰 키워드

사람들이 이미 검색할 가능성이 높은 넓은 입구다.

- 발달장애
- 지적장애
- 특수교육
- 느린학습자
- 읽기 쉬운 책
- AI 교육

### 날자의 고유 키워드

날자꾸러미가 만들어 가는 고유 언어다.

- 유추력
- 날자꾸러미
- AI-아날로그 융합 학습
- 성장기록서
- 배운 것이 삶으로 이어지도록

### 다리 역할 키워드

큰 키워드와 날자의 고유 언어를 연결한다.

- 문해력 지원
- 일상 전이
- 자기결정
- 학습권
- 쉬운 정보
- 읽기이해
- 표현 지원

## 글 발행 시 적용 기준

새 글을 발행할 때 다음을 확인한다.

1. 제목이나 설명에 독자의 질문을 나타내는 익숙한 말이 들어가는가? 확인하지 않은 검색량을 전제하지 않는가?
2. 본문에 날자가 이름 붙이고 싶은 고민이 분명히 드러나는가?
3. 큰 키워드, 날자의 고유 키워드, 다리 역할 키워드가 억지 없이 연결되는가?
4. 중요한 기둥글이면 `/topics/`에 연결했는가?
5. 본문의 주장마다 직접 확인한 공식·연구 원문이 연결되고, 설명·가상 예시와 연구 결과가 구분되는가?

Google/Bing의 수동 색인 요청과 검색 성과 검토는 정기 발행에 포함하지 않는다. 로그인된 상태에서 사용자가 별도로 요청할 때만 `docs/search-performance-review.md`의 절차를 따른다.

## 비브랜드 검색 유입 기준

검색을 고려했다는 말은 제목을 그대로 입력했을 때 글이 나오는 상태를 뜻하지 않는다. 날자나 글 제목을 모르는 사람이 자신의 질문을 일반 검색어로 입력했을 때 글을 발견할 수 있어야 한다. 중요 기둥글은 아래 기준을 추가로 따른다.

1. 글마다 하나의 대표 비브랜드 검색어(`seo.primary_query`)를 정한다.
2. 검색하는 사람이 원하는 답을 한 문장으로 적어 검색 의도(`seo.search_intent`)를 기록한다.
3. 같은 의도를 다른 말로 표현한 보조 검색어(`seo.secondary_queries`)를 두 개 이상 둔다.
4. 더 넓은 범주의 유입어가 필요하면 다리 검색어(`seo.bridge_queries`)를 둔다. `발달장애 학습`, `발달장애 성장`처럼 범위가 넓은 말은 해당 글이 실제로 다루는 대상과 같다고 간주하지 않는다.
5. 대표 검색어는 description과 본문 도입부에 자연스럽게 넣고 태그에도 연결한다. 제목에 대표 검색어를 반드시 넣거나 맨 앞에 둘 필요는 없다. 다리 검색어는 description·태그·도입부와 주제 허브에서 자연스럽게 연결한다.
6. `발달장애`를 다리 검색어로 쓸 때는 발달장애가 지적장애인과 자폐성장애인 등을 포괄하는 넓은 범주이며, 해당 글은 그중 지적장애인을 중심으로 한다는 범위 설명을 도입부에 둔다.
7. 대표 검색어에 답하는 중간 제목과 핵심 요약을 두고, 제목만 바꾼 뒤 본문이 다른 질문에 답하는 일을 막는다.
8. 새 글의 `related`에 관련 기존 글의 slug를 넣어 연결한다. 기존 글에서는 기존 `related` 목록에 새 글의 slug 한 줄을 추가하는 것만 허용한다. `related_posts`는 이 저장소에서 사용하지 않는다.
9. 검색 결과를 확인하되, 검색량이나 경쟁도를 확인하지 않은 표현을 “사람들이 이미 찾는 말”이라고 단정하지 않는다.
10. 새 글의 `date`, `updated`, `last_modified_at`은 실제 게시일의 Asia/Seoul 날짜로 맞춘다. 기존 글은 관련 글 한 줄을 추가해도 날짜나 다른 메타데이터를 변경하지 않는다.
11. 제목은 독자의 질문이나 글의 핵심을 자연스럽게 드러낸다. 질문형·한 문장 서술형 등 여러 형식을 허용하되 같은 꼴이 연달아 이어지지 않게 한다. `지적장애인(발달장애인) 주제: 기준·방법` 꼴을 반복하지 않으며, 특정 형식이나 제목 앞부분의 검색어 배치를 강제하지 않는다. 구체적인 원고 제목은 사용자가 정한 로컬 글감 목록의 제목 기준을 따른다.

키워드 반복 횟수를 늘리는 것은 목표가 아니다. 한 글은 하나의 검색 의도에 분명히 답하고, 날자의 고유 관점과 근거를 더해 다른 결과와 구별되어야 한다.

## 기존 게시 글의 보존

- 기존 게시 글의 제목·설명·본문을 변경하지 않는다. 태그·검색어·출처·게시일·수정일 등 다른 메타데이터도 자동으로 바꾸지 않는다.
- 새 글에서 기존 글로 링크하고, 필요한 기존 글의 관련 글 목록에 새 글의 slug 한 줄을 추가하는 것만 허용한다. 기존 관련 항목의 삭제·교체·재정렬은 하지 않는다.
- 기존 글의 `related`가 없어 한 줄 추가만으로 연결할 수 없거나, 기존 구조 때문에 검증이 실패하면 본문이나 다른 필드를 고쳐 해결하지 않고 필요한 조치를 보고한다.
- 정기 발행에서 성과 재평가에 따라 기존 글을 수정하는 절차는 사용하지 않는다. 검색 기록에 남은 과거 검토 일정도 실행 지시로 따르지 않는다.

수동 검색 검토는 `docs/search-performance-review.md`에 관찰 결과를 남기는 별도 작업이다. 그 검토 자체는 기존 글의 수정 권한이 아니다.

## 중요 기둥글 기준

다음 주제에 해당하면 중요 기둥글로 본다.

- 학습권
- 문해력
- 유추
- AI
- 쉬운 정보
- 자기결정
- 성인 지적장애
- 안전 문해력
- 발달장애 학습·성장
- 날자꾸러미 설명

새 중요 글은 `/topics/` 연결 여부를 확인한다. GitHub Pages·IndexNow·네이버 검수 초안의 기존 워크플로는 유지하고, Google/Bing의 수동 절차는 정기 발행의 완료 조건으로 삼지 않는다.
