# 중등도 지적장애 경험 연구 백서·공개 초안 설계

## 목적

기존 원고 「중등도 지적장애(IQ 50 전후)의 주관적 경험 세계: 실증 문헌 종합」을 근거 수준과 해석의 경계가 분명한 내부 연구 백서로 개정한다. 동시에 백서의 핵심 쟁점을 날자 아카이브 독자가 한 번에 하나씩 이해할 수 있도록 공개용 글 5편의 비공개 초안으로 분리한다.

이번 작업은 연구 문서와 게시 후보 초안을 만드는 단계다. Jekyll `_posts` 추가, 홈페이지 노출, 배포, 검색엔진 색인 요청은 범위에 포함하지 않는다.

## 기본 원칙

1. `/Users/yuny/Downloads/`의 원본은 수정하지 않는다.
2. `IQ 50 전후`를 사람이나 경험 세계를 대표하는 고정 표지로 사용하지 않는다.
3. 지적 기능 점수와 함께 적응행동, 의사소통 특성, 병인, 감각 조건, 환경과 필요한 지원의 차이를 설명한다.
4. 당사자 직접 보고, 인지·언어 과제, 임상 관찰, 실무 문서, 필자의 해석을 같은 수준의 근거처럼 섞지 않는다.
5. 공개 초안에서 확정적으로 검증하지 못한 수치와 절대 표현을 사용하지 않는다.
6. 공식 명칭과 참고문헌 제목은 원문을 유지하되 공개 서술은 지적장애인·지적장애 표현을 중심으로 한다.
7. 당사자의 내면을 낭만화하거나 결손으로 환원하지 않는다.

## 산출물

### 1. 내부 연구 백서

저장 위치:

`docs/research/moderate-intellectual-disability-lived-experience-evidence-review.md`

백서는 다음 구조를 따른다.

- 문서의 목적과 사용 범위
- 용어와 범위: 중등도, IQ, 적응행동, 병인과 개인차
- 근거를 읽는 네 단계
  - A: 중등도 지적장애 당사자 직접 보고 또는 직접 표본
  - B: 경도·중등도 혼합 표본 또는 지적장애 일반 연구
  - C: 인접 집단·특정 병인·임상 및 실무 근거
  - D: 날꾸의 해석과 설계 가설
- 인지와 작업기억
- 언어와 의사소통
- 감각과 통증
- 감정과 사회적 경험
- 동의, 관계와 착취 위험
- 콘텐츠 재현 원칙
- 근거 공백과 추가 검증 목록
- 참고문헌

각 주요 주장에는 근거 등급을 표시한다. 연구 결과를 생활 언어로 번역한 문장은 `해석`으로, 날꾸 제품·콘텐츠에 적용한 문장은 `설계 시사점`으로 분리한다.

Grokipedia, Wikipedia, ResearchGate는 최종 근거로 사용하지 않는다. 원 논문을 확인할 수 없으면 해당 주장을 근거 공백 목록으로 이동하거나 삭제한다. 감각 손상 배수, 청소년 피해 경험 80% 등 원문 엄밀성이 낮다고 표시된 수치는 원문과 모집단을 확인하기 전까지 본문 결론에 사용하지 않는다.

### 2. 공개용 비공개 초안 5편

저장 위치:

`drafts/moderate-intellectual-disability-series/`

파일과 중심 질문:

1. `01-expression-is-not-the-limit-of-understanding.md`
   - 말로 표현된 것만으로 이해 능력을 판단하면 안 되는 이유
2. `02-when-yes-is-not-informed-agreement.md`
   - 지적장애인의 “예”는 언제 진짜 동의가 아닌가
3. `03-private-speech-is-not-just-problem-behavior.md`
   - 혼잣말을 문제행동으로만 보면 놓치는 것
4. `04-pain-and-sensory-needs-mistaken-for-intellectual-disability.md`
   - 통증과 감각 문제가 지능 탓으로 오인될 때
5. `05-safety-literacy-against-counterfeit-friendship.md`
   - 친구라는 이름의 착취를 알아차리는 안전 문해력

각 초안은 다음 요소를 포함한다.

- 게시 후보 제목
- description
- 권장 category와 tags
- 검색 전략상 큰 키워드, 날자의 고유 키워드, 다리 역할 키워드
- 첫 문단
- 핵심 요약
- 5~7개 본문 절
- 결론
- 검증된 출처 목록
- 관련 기존 글과 `/topics/` 연결 제안
- 공개 전 확인할 주장과 수치

초안에는 Jekyll 게시용 `date`나 `updated`를 넣지 않는다. 날짜는 실제 게시 당일에 정한다. `_config.yml`의 `exclude` 목록에 `drafts`가 이미 포함되어 있지 않다면, 공개 빌드 유입을 막기 위해 `drafts`를 제외 대상으로 추가하고 검증 스크립트로 확인한다.

## 편집 기준

### 제목과 범위

백서 제목은 「중등도 지적장애인의 경험을 이해하기 위한 실증 문헌 종합」으로 한다. 부제는 「인지·언어·감각·감정·관계에서 드러나는 지원의 조건」으로 한다.

공개 글은 한 편에 한 가지 독자 질문만 다룬다. “중등도 지적장애인의 세계”처럼 집단 전체의 내면을 대표한다고 오해할 제목은 사용하지 않는다.

### 문장 강도

다음과 같은 절대 표현은 근거가 직접 뒷받침하지 않는 한 사용하지 않는다.

- 머릿속에는 다 있다
- 어느 경우에도 환각이나 망상이 아니다
- 감정 기능은 온전하다
- 미래는 불안의 안개다
- 손상된 것은 인터페이스뿐이다

대신 관찰 범위와 불확실성을 드러내는 표현을 쓴다. 예를 들어 “혼잣말만으로 환각이나 망상으로 판단해서는 안 된다”, “표현된 말이 이해 능력의 전부를 보여 주지 않을 수 있다”처럼 쓴다.

### 안전과 존엄

- 보호자나 지원자의 관찰보다 당사자에게 직접 묻는 절차를 우선한다.
- 특정 행동을 지적장애 탓으로 돌리기 전에 통증, 감각, 환경과 의사소통 기능을 확인한다.
- 묵종을 당사자의 성격 결함으로 설명하지 않는다.
- 착취 예방을 이유로 관계와 자립을 제한하는 결론으로 가지 않는다.
- 위험 신호와 함께 당사자의 선택, 상호성, 도움 요청 경로를 설명한다.

## 검증 방법

### 백서 검증

- 모든 핵심 주장에 근거 등급이 있는지 확인한다.
- 참고문헌 URL이 본문 주장과 연결되는지 확인한다.
- 미검증 수치가 결론에 남지 않았는지 검색한다.
- `IQ 50의 세계`, `어느 경우에도`, `온전하다`, `40~100배`, `80%` 등 위험 표현을 검색한다.
- 직접 보고와 필자의 해석이 명시적으로 구분되는지 확인한다.

### 공개 초안 검증

- 각 글이 하나의 중심 질문만 다루는지 확인한다.
- 제목·description·태그·도입부에 검색 전략의 세 키워드 층위가 자연스럽게 연결되는지 확인한다.
- 기존 아카이브 글과 중복되는 설명은 내부 링크로 줄이고 새 질문에 집중한다.
- 참고자료의 공식 명칭을 제외한 공개 문장에서 발달장애인·발달장애 표현이 남지 않았는지 확인한다.
- 5편 모두 `drafts/` 아래에 있고 production Jekyll 빌드 결과에 포함되지 않는지 확인한다.

### 저장소 검증

- `JEKYLL_ENV=production bundle exec jekyll build --trace`
- `ruby scripts/verify_site.rb`
- `ruby scripts/verify_pinned_home.rb`
- `git diff --check`

## 완료 조건

- 원본 파일이 변경되지 않는다.
- 내부 백서가 근거 등급과 해석 경계를 포함한다.
- 공개용 비공개 초안 5편이 완성된다.
- 초안이 production 사이트에 노출되지 않는다.
- 기존 홈페이지의 왼쪽 고정 선언문과 오른쪽 최신순 목록이 바뀌지 않는다.
- 저장소 검증 명령이 모두 성공한다.
- 공개 게시, 커밋 푸시, 자동 게시 순서 등록은 별도 사용자 승인 전 수행하지 않는다.
